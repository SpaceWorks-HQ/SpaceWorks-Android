# White-label builds

1. Clone this repo recursively: `git clone --recurse-submodules https://github.com/SpaceWorks-HQ/SpaceWorks-Android.git`. Keep `design/` pinned; review token changes before updating its commit.
2. Edit only `branding/brand.json` and assets next to it. Set `app_name`, a unique `android_application_id` owned by your organisation, `app_icon` (SVG containing paths and optional rounded rectangles), and `theme_tokens` (same semantic light/dark token shape). Supply your actual support and privacy HTTPS URLs before store submission; null values intentionally indicate owner setup is outstanding.
3. Set `server_url` to your HTTPS deployment origin to lock the build to it. Leave null for first-launch server entry. The app performs generated `/api/v1/health/` validation before entering the shell. Official builds never bundle a staging URL or credentials.
4. Install Java 21, Python 3, Android SDK platform 36/build tools and run `./gradlew lint test assembleDebug`. Gradle reads the identity/name/server directly and regenerates the semantic Compose theme and vector launcher icon. `./gradlew :app:openApiGenerate` regenerates the API client.
5. Create your own Google Play Console application and enable Play App Signing. Store your upload keystore/passwords in CI secrets. Configure release signing in the private build environment; the repository does not include an owner upload key or release signing configuration. Review the signed release's package ID, certificate, version and icon before upload.
6. Create your own Firebase project and Android app matching the application ID. Enable/link Play Integrity to your own Play application, register the actual signing certificates and configure the backend app allowlist. Inject runtime Firebase configuration privately; token registration is gated and must not start from onboarding or demo. APNs applies to the companion iOS build and needs your own Apple account and key.
7. Complete privacy policy/Data safety details, reviewer demo account, closed testing and signing with your own accounts in A7/A8. Build a signed AAB (`bundleRelease`) after release signing is configured and publish through your Play Console.

No secrets, signing keys, `.p8` files, Firebase config or test credentials are committed. Ordinary interface text uses the owner-supplied Gilroy Regular, Medium, Semibold and Bold faces with native Material typography and system font scaling. The latest owner instruction authorizes these provided assets; keep their provenance and use them under the applicable Gilroy license. Debug APKs and unsigned CI release outputs are development/compile evidence. See [RELEASE-READINESS.md](RELEASE-READINESS.md) for the exact checks, owner inputs, privacy review and distribution evidence. The owner's batch workflow permits tested phases on `dev` before the final reviewed merge.

Auth/intro branding also reads `logo_symbol`, `logo_symbol_reversed`, `logo_symbol_one_colour_ink` and the equivalent `logo_stacked` paths from `brand.json`. Supply native-vector-compatible SVG masters with their original view boxes; keep the dedicated symbol/stacked clear space and do not animate/recolor/tint the logo. Mobile motion comes from this app repository's `tokens/mobile-motion.json` and UX guidance from `docs/mobile-auth-ux-spec.md`; system animation-off settings suppress custom movement/opacity transitions. The existing Design submodule supplies brand assets and semantic colors; mobile-specific files are maintained in the app repositories. The default open-source Unbounded accent font and its conversion provenance/licence are in `docs/licenses/`; normal text uses the supplied Gilroy family. The `font_regular`, `font_medium`, `font_semibold` and `font_bold` paths select the four WOFF1 inputs; `scripts/brand_fonts.py` losslessly repackages their sfnt tables into native Android TTF resources during `prepareBrand`. See [font provenance](licenses/Gilroy-native-fonts.md).

Native Google acquisition uses Credential Manager 1.6.0 and the compiler-compatible GoogleID 1.1.1. Register your own package/signing fingerprints and server OAuth web client audience, and publish the documented `social_auth.google` configuration. Do not substitute an Android OAuth client ID for the server web audience. Missing native attestation/session contract still prevents production sign-in. The small Google G is Google's unchanged official sign-in asset ([source](https://developers.google.com/static/identity/images/g-logo.png), [branding requirements](https://developers.google.com/identity/branding-guidelines)); provider styling is intentionally independent of the app palette. No client secret is bundled. DEBUG preview providers never call Google/Apple/SSO/SMS SDKs or your backend; release omits their implementation and Explore demo entry.
